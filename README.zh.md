# ros-hotplug-by-dsh

> **一句话**：率先将 DeepSeek Harness（DSH）的「时空组合性」应用于**具身机器人能力的热插拔**, 并给出**可复现实现 + 教学级 demo**.

---

# 环境准备

1. **机器人侧(ROS2 + 仿真)**
   - 终端 1: `ros2 launch rosbridge_server rosbridge_websocket_launch.xml`(rosbridge 通道)
   - 终端 2: `source /opt/ros/humble/setup.bash && source /root/venvs/robo/bin/activate`, 然后运行 `python3 src/ros2/sim_bridge/sim_bridge/two_arm_server.py --view`(双臂 MuJoCo 可视化)

2. **DSH web(面板与能力体系)**
   - `bash src/setup.sh` 一键安装: 能力挂载服务行、能力面板包、robo preset(路径集中化)
   - 重启 `dsh web`, 页面刷新后输入区上方出现**能力面板**

3. **建会话**
   - 新建会话选择「机器人任务」→ 即得到最小工具集机器人 agent(arm_status/take_object + 能力面板)

# 场景示例

## 创建会话

点击「机器人任务」, 可以创建一个最小工具集的会话. 会话内 agent 只有两个机器人工具: `arm_status`(感知某条臂是否具备可用末端)与 `take_object`(让该臂去拿东西).

![创建会话](docs/assets/创建会话.png)

## web能力面板

红框处是机器人能力面板, 可以装配不同的机械臂末端插件, 以及视觉传感器.

面板自上而下:
- **操作行**: 刷新 | 全部复位 | 臂A复位 | 臂B复位 | 折叠(折叠后只占一行)
- **臂行**: 每臂一个下拉框(「不装配」/ 各末端版本), 行尾显示物理末端
- **感知行**: 下拉框(「不装配」/ camera_detect 等传感器能力)
- **拿小球行**: 选「不指定臂/臂A/臂B」+ 去拿小球(把消息发给 agent, 由 agent 判断执行)
- **小球行**: 显示小球当前位置 + x/y 输入 + 「设定」(设定后小球立即移动)

![能力面板](docs/assets/能力面板.png)

## 装配末端

- 通过 web 的点击, 可以丝滑的对机械臂末端装配不同的插件
- 臂A(深蓝)、臂B(橙)、夹爪(翠绿)、吸盘(绛紫红)、不装配(浅灰)

![装配末端](docs/assets/装配末端.gif)

## 插件切换与抓取小球

- agent 只需要关心是否装配了机械臂末端, 不需要关心机械臂末端具体如何实现(硬件屏蔽). 当装配了末端, 给 agent 发消息就可以执行抓取小球动作: 「用臂A去拿小球」→ agent 先`arm_status(A)`(ready) → 再 `take_object(A)`(策略在末端实例内部) → 返回命中/未命中.
- 面板拿小球行还支持「不指定臂」: 发「去拿小球」, 由 agent 自行感知选择.

![插件切换与抓取小球](docs/assets/插件切换与抓取小球.gif)

## 插件能力增强

- 只有 grasp 1.2.0 时, 末端为**盲抓**: 移向该臂预设点(臂A 预设点 [0.3,-0.3]、臂B [0.3,0.3]), 小球不在预设点则「未命中」.
- 感知槽再挂上 camera_detect 后, 视觉拦截器把小球位置注入执行链 → 末端按实际位置**精准抓取**.
- 卸载视觉传感器后自动回退盲抓; 视觉数据不可用时 fail-open 放行盲抓, 链路不中断.

![插件能力增强](docs/assets/插件能力增强.gif)

# 不足与扩展

## 不足

- 为突出插件化的思想, 对机器人侧做了最简化处理: 无物理碰撞、抓取判定 = 末端与球的距离阈值(0.05 m, 非接触判定); 仿真视觉 = 读 /joint_state 状态回传的 ball 字段, 非真实相机.
- grasp 1.0.0/1.1.0 与 suction 1.0.0 是换版演示版本(touch 发布即回, 无命中判定); 视觉注入链仅对 grasp 1.2.0 生效.
- 面板 /cap-mount 写入口无鉴权, 边界为单用户可信环境.

## 扩展

- 能力装载的标准协议与合法性校验(已有 sha256 准入 + kind 路由): 进一步加发布者签名、机器可读能力元数据.
- 逻辑-物理对账: 面板刷新/挂载服务启动时按物理态重建挂载记录(「重建挂载」动作).
- 真实硬件(ros2_control hardware_interface)与真实视觉相机; 接触判定与抓取后小球随末端运动的物理仿真, 让「成功率」有物理意义.
- 多用户鉴权、换挂零窗口(蓝绿两段式)、agent 评测自动化(agent vs oracle vs random).
