# BiAdapt（双臂自适应机器人）· 项目计划

## 一、项目目标

在纯仿真中搭建一台"差速底盘 + 万向轮 + 躯干 + 双臂 + 头部 RGB-D + 激光雷达"的移动操作机器人，核心演示**本体自适应 / 故障重构**：双臂正常端托盘，注入单臂失效后，系统自动从关节数据检测故障，并在高层任务规划层改用另一侧臂完成任务。以自然语言下达指令，云端 LLM 做高层任务规划。

学习目标：以具身系统集成视角，系统掌握 ROS2 中间件、仿真、运动学、导航建图、任务规划、故障诊断等知识，边做边学，不计时间成本。

## 二、已定边界

1. 底盘会移动，流程 = 开机 -> 建图/导航到桌边 -> 双臂工作（此时底盘不动）。
2. 故障粒度 = 整臂禁用；失效模式默认 = 关节卡死（freeze），注入接口（节点/话题/关节）在阶段 5 开始前钉死，其余失效模式列为后续扩展。
3. 自适应发生在高层任务规划层（LLM 消费故障信号后重规划）。
4. 中间件 ROS2（必须，全栈学习）；纯 CPU 仿真（GPU 不可用）。
5. 本体 = 开源机械臂 URDF 拼装，不从头手写整机。
6. 抓取 = 接触仿真（非吸附）；托盘 = 低重心、宽底座、高摩擦底面；正常双臂两边一起拿起，故障后单手边缘抓取（托盘初始在单手可及、靠桌边）；"单手长距离推到桌边"为进阶可选，不压验收关键路径。
7. 建图/导航/点云 SLAM 以学习为目标，简单跑通。
8. 评测 = 自定义 benchmark；真机/预算不考虑。

## 三、环境事实

- Ubuntu 24.04.5 LTS，ROS2 Jazzy 已安装（`/opt/ros/jazzy`）。
- Gazebo、MuJoCo 未安装。
- Python 3.12.3。
- GPU 不可用（纯 CPU 仿真），大模型走云端 API。
- WSLg 可用（`DISPLAY=:0`），仿真窗口可弹窗。

## 四、技术路线

路线一：Gazebo Harmonic（ROS2 Jazzy 官方配套）+ ROS2 全栈（ros2_control、lifecycle、nav2、slam_toolbox、rtabmap）+ 云端 LLM 高层规划 + 技能原语 + 残差故障检测。

资源回收分层：规划层移除左臂技能 + 控制层 lifecycle 原子卸载。

## 五、阶段规划（7 个大阶段）

每个大阶段的子任务在该阶段开始时拆解：先给该阶段完整子任务清单，再按"一步一天内、完成一步确认一步"执行。阶段 1 子任务清单见任务清单文件。

### 阶段 1：机器人建模与仿真可视化 + 接触可行性门禁
- 目标：Gazebo 搭起整机，能 spawn、可视化、关节手动动起来；并以最小接触抓取验证物理可行性。
- 验收：一条 `ros2 launch` 启动整机；Gazebo/RViz 可见；TF 树正确；`/joint_states` 有数据；发指令关节能转；单臂接触夹起一个简单刚体（方块/圆柱）成功且可复现，软件渲染实时因子满足接触仿真（门禁）。
- 风险：URDF 拼装与 ros2_control 配置量大；传感器插件；软件渲染实时性。

### 阶段 2：底盘移动与建图导航
- 目标：差速底盘移动，2D 建图 + 导航到桌边；rtabmap 点云 SLAM 概念简单跑通。
- 验收：机器人自主导航到桌边指定点，地图正确，无人工干预。
- 风险：nav2 配置、激光/里程计仿真、软件渲染性能。

### 阶段 3：双臂运动学与接触抓取（托盘）
- 目标：双臂 IK 控制，双臂协同夹起带载托盘并搬移（无故障）。
- 验收：双臂抬起带载托盘移动到目标位，载物不掉，接触夹持可复现。
- 风险：双臂协同接触夹持不稳定（核心风险）；IK/MoveIt2 配置。单臂边缘抓取作为阶段 5 目标，本阶段不做。

### 阶段 4：LLM 任务规划（无故障）
- 目标：自然语言指令 -> 云端 LLM 高层规划 -> 技能调用（导航 + 双臂搬运）。
- 设计约束：规划器与执行器分离；技能原语注册表 + 执行器做成独立接口化组件（技能 = 可枚举描述 + 可调用入口）；规划器只输出技能序列，不直接耦合 ROS2 调用。该约束同时服务阶段 5 的故障移除与阶段 6 的 DSH 承载复用。
- 验收：自然语言"把托盘搬到 B 台"自动规划执行成功。
- 风险：LLM 结构化输出不稳定（schema 约束 + 校验）；技能粒度设计。

### 阶段 5：故障检测与本体自适应（核心验收）
- 目标：注入左臂关节卡死，残差检测发现故障，LLM 消费信号重规划（单手边缘抓取托盘），完成任务。
- 前置设计项：阶段 5 开始前钉死失效模式（默认关节卡死）与注入接口（哪个节点、哪个话题、哪些关节）；残差特征、阈值、"N 步内检测"的"步"都围绕该模式设计。
- 验收：故障注入后 N 步内检测并切换策略，任务成功率达标（指标见阶段 7）。
- 风险：残差阈值误报/漏报、重规划正确性、注入机制。

### 阶段 6：DSH 承载规划 agent + 插件化热插拔（进阶）
- 目标：把规划器前端换成 DSH agent，技能注册为 DSH 工具，左臂故障 = 工具热插拔移除；注册表/执行器复用阶段 4 组件。
- 验收：故障后 DSH agent 工具集移除左臂，LLM 在剩余工具集重规划成功。
- 风险：DSH 与 ROS2 桥接复杂度（规划器前端重写，注册表/执行器复用，返工约三分之一）。

### 阶段 7：自定义 benchmark 与评测
- 目标：故障注入协议 + 指标做成可复现 benchmark，多组实验输出结果。
- 验收：一键复现；报告成功率、检测步数、切换步数、单手/双手轨迹差异度。
- 风险：指标定义、实验可复现性。

## 六、任务模板

每个任务固定写全七项：

1. 为什么做
2. 在整机项目中的作用
3. 输入
4. 输出
5. 边界与风险
6. 验收方式
7. 详细步骤（步骤中嵌入可复用接口的名称与用途，不写完整业务实现）

## 七、执行约定

1. 每次只推进一个小步，一步以"一天内可完成且有可复现验收"为上限；完成一步后等确认再给下一步。
2. 每个任务按第六节模板写全七项。
3. 业务代码由用户实现，导师只做指导与审阅。
4. 计划、任务清单、风险清单随推进持续维护。
5. 涉及版本/来源一律标注并核对，不用过时信息。
