# 任务 1.6：配 ros2_control，关节可动

状态：已规划，待执行

## 1. 为什么做

1.3 用 gz 内置 DiffDrive 插件让底盘动，但那不是 ROS 生态的控制方式。ros2_control 是 ROS2 控制机器人的标准架构，MoveIt2、nav2 都基于它。1.6 把整机纳入 ros2_control，是阶段 3 双臂抓取、阶段 5 故障重构（控制层原子卸载）的基础。

## 2. 在整机项目中的作用

控制层。整机（底盘 + 双臂）统一到一个 controller_manager 下管理：底盘 diff_drive_controller、双臂 joint_trajectory_controller、joint_state_broadcaster。阶段 5 单臂失效时，停掉对应臂的 controller 就是"控制层原子卸载"。

## 3. 输入

- 1.5 的整机 xacro + 自定义 world。
- 已装：`controller_manager`、`controller_manager_msgs`、`gz_ros2_control`、`hardware_interface`、`ros2_control_cmake`。
- **需补装**：`ros-jazzy-ros2-controllers`（提供 joint_state_broadcaster、joint_trajectory_controller、diff_drive_controller、forward_command_controller）。
- 官方接口（已核对 [gz_ros2_control 文档](https://github.com/ros-controls/gz_ros2_control/blob/humble/doc/index.rst)）：
  - URDF `<ros2_control>` 标签 + `<hardware><plugin>gz_ros2_control/GazeboSimSystem</plugin>`。
  - URDF `<gazebo>` 插件 `gz_ros2_control-system`（name `gz_ros2_control::GazeboSimROS2ControlPlugin`）。
  - 控制器 YAML（controller_manager + joint_state_broadcaster + 各 controller）。

## 4. 输出

- 整机纳入 ros2_control：底盘 diff_drive_controller + 双臂 joint_trajectory_controller（左右分两个）+ joint_state_broadcaster。
- 移除 1.3 的 gz DiffDrive 插件和 JointStatePublisher 插件。
- 通过 controller 发指令让关节转动；`/joint_states` 由 joint_state_broadcaster 发布。

## 5. 边界与风险

- 只配控制 + 关节可动，不做 IK、不做轨迹规划（阶段 3）。
- 风险 a：`ros2_control` 标签里 command/state interface 与关节类型匹配错误（revolute/continuous 用 position，轮子用 velocity）。
- 风险 b：gz_ros2_control 插件与 1.3 的 DiffDrive/JointStatePublisher 插件冲突（odom、joint_states 重复发布）。
- 风险 c：controller_manager 的 lifecycle 状态需要 activate，spawner 要正确加载。
- 风险 d：双臂关节名带前缀（left_/right_），YAML 里 joints 列表要写全名。
- 风险 e：head_joint 是 continuous（1.5 为 sensor 不 lump 改的），不在 ros2_control 里时是自由关节，需确认它停在初始位。

## 6. 验收方式（可复现）

1. `ros2 control list_controllers` 显示 joint_state_broadcaster、diff_drive_controller、left_arm_controller、right_arm_controller 均为 active。
2. `ros2 topic echo /joint_states --once` 的 name 列表包含双臂 12 个关节 + 两个轮子。
3. 发 cmd_vel 底盘移动（diff_drive_controller）。
4. 用 `ros2 topic pub /left_arm_controller/joint_trajectory ...` 或命令行让某个关节转，Gazebo 里对应关节动。
5. `/joint_states` 的 position 随关节转动更新。

## 7. 详细步骤

### 步骤 1：装 ros2_controllers

- `sudo apt install ros-jazzy-ros2-controllers`
- 验证：`ros2 pkg list | grep ros2_controllers`，`ros2 control list_hardware_interfaces` 可用。

### 步骤 2：URDF 加 `<ros2_control>` 标签

- 在 xacro 里加 `<ros2_control name="GazeboSimSystem" type="system">`，内含：
  - `<hardware><plugin>gz_ros2_control/GazeboSimSystem</plugin></hardware>`
  - 每个关节的 `<joint>`，定义 command/state interface：
    - 轮子 `left_wheel_joint`、`right_wheel_joint`：`command_interface name="velocity"` + `state_interface` position/velocity。
    - 双臂 12 个关节：`command_interface name="position"` + `state_interface` position/velocity。
- 关节名带前缀（left_shoulder_pan_joint 等）。

### 步骤 3：URDF 加 `<gazebo>` gz_ros2_control 插件

- 模型级 `<gazebo>` 里加：

```xml
<plugin filename="gz_ros2_control-system" name="gz_ros2_control::GazeboSimROS2ControlPlugin">
  <robot_param>robot_description</robot_param>
  <robot_param_node>robot_state_publisher</robot_param_node>
  <parameters>$(find biadapt_description)/config/biadapt_controller.yaml</parameters>
</plugin>
```

### 步骤 4：移除 1.3 的旧插件

- 删掉 xacro 里的 DiffDrive 插件（wheel_gazebo 宏里的 `gz-sim-diff-drive-system`）。
- 删掉 JointStatePublisher 插件（`gz-sim-joint-state-publisher-system`）。
- 因为 diff_drive_controller 发 odom/tf，joint_state_broadcaster 发 /joint_states，旧的 gz 插件不删会重复发布。

### 步骤 5：写控制器 YAML

- `config/biadapt_controller.yaml`：
  - `controller_manager`：update_rate、四个 controller 的 type。
  - `joint_state_broadcaster`（无 joints，自动广播所有 state_interface）。
  - `diff_drive_controller`（type `diff_drive_controller/DiffDriveController`，left/right wheel，wheel_separation/radius，velocity 接口）。
  - `left_arm_controller`、`right_arm_controller`（type `joint_trajectory_controller/JointTrajectoryController`，各 6 个关节，position 接口）。
- 左右臂分两个 controller，是阶段 5 单臂失效时原子卸载的前置。

### 步骤 6：launch 加 spawner

- `gazebo.launch.py` 里加 `controller_manager` spawner 节点（`spawner` 可执行，来自 `controller_manager` 包）。
- spawn 4 个 controller：joint_state_broadcaster、diff_drive_controller、left_arm_controller、right_arm_controller。
- bridge 里移除 `/odom`、`/tf` 的桥接（diff_drive_controller 现在 ROS 原生发 odom/tf，不再从 gz 桥）。

### 步骤 7：验证

- 按第 6 节逐条执行。

3. controller_manager 的 update_rate 影响什么？position 接口的 position_proportional_gain 是什么（P 控制）？
4. joint_state_broadcaster 和 1.3 的 JointStatePublisher 插件有什么区别？为什么 1.6 要移除 JointStatePublisher？
5. joint_trajectory_controller 和 forward_command_controller 的区别？让关节走一条轨迹用哪个？
6. diff_drive_controller 和 1.3 的 DiffDrive 插件有什么区别？迁到 ros2_control 后 odom 和 tf 由谁发、怎么发？
7. spawner 节点起什么作用？controller_manager 和各 controller 的 lifecycle 状态怎么管理（configured/active）？
