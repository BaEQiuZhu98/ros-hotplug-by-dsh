# 答题审阅标准

适用：每个任务完成后，对学员提交的理解验证题答案进行审阅。本文件是硬约束，审阅时逐条对照。

## 一、判定流程

1. 先读任务定义 `doc/tasks/<n>.md` 中"输出"与"验收方式"两节，列出逐条验收清单。
2. 逐题对照清单判定：完全满足、部分满足、不满足。
3. 任一"不满足"，或验收清单存在未被答案覆盖的条目，结论一律为不通过。
4. 结论只给三档：通过 / 补充后重审 / 不通过，每档附依据，不做模糊表述。

## 二、判据

1. 逐条对照验收标准。任务定义里的每一条"输出"和"验收方式"都是判定项，不因题目数量少而放过。
2. 每题必须写全"是什么 + 为什么"。定义之外要给出机制、原理或取舍理由；只给结论式短句视为未完成。
3. 明确问 N 项就答 N 项。题目列出三类关节、两个方向、多个作用时，缺项即不通过，不以"其余正确"折中。
4. 必须给实例证据。涉及读模型、看工具、跑命令的题，用实际文件内容、实际输出或命令行结果作答，不得停在概念复述。
5. 工具类题必须双向回答。能查出什么、检不出什么，缺一不可。
6. 错误表述必须纠正并给出正确表述，不接受"方向对"式的模糊评价。
7. 答题质量较上一任务明显下滑时直接指出，并说明对后续任务的影响，不因进度压力降低标准。
8. 审阅意见写入 `.myfile/queryAndAnswerAfterTask.md` 对应任务小节，每题固定"评价 / 参考 / 考察点"，末尾给总体评价与结论。

## 三、常见不通过情形

- 题目问三类关节，只答两类：缺项，不通过。
- 概念题只给一句结论，无机制：补充后重审。
- 工具题只答"能查什么"，不答"查不出什么"：补充后重审。
- 要求"举一条关节链"，只答识别方法：不通过。
- 答案与任务"输出"要求不对应，例如 1.2 未给出任何关节树：不通过。

## 四、审阅输出格式

每题固定三段：评价（对与缺，直接给判定）、参考（正确内容与至少一个具体例子）、考察点（该题真正要考的能力）。

总体评价写三部分：达标项、不达标项、结论与下一步。结论为"补充后重审"时，列出必须补齐的具体条目，不写泛泛的改进建议。
