# DSH 时空组合性（Spatiotemporal Compositionality）详解

> 这是本项目的方法论基石，也是教学核心文档。目标：把 DSH 的「时空组合性」讲成一个可复用、可迁移到机器人热插拔的心智模型。
> 内容依据：DSH 源码/文档（`dsh-scope` 包、`editing-cordis-compositions` skill、`cordis-plugin-development` skill）。

---

## 0. 一句话

**DSH 里任何能力（工具、技能、服务、提示词片段）都不是写死的，而是由「插件行」组合出来的；这个组合同时具有空间结构（分层、分域地摆放）和时间结构（挂载、撤销、版本演进）。**

两条轴由同一个锚点绑定，保证不打架：

> **注册的上下文，同时决定这项注册的「可见性」和「生命周期」。**

---

## 1. 空间轴：谁看得见谁（Scope / Layer / Plane / Realm）

### 1.1 两个「平面」(plane)

| 平面 | 是什么 | 生命周期 |
|---|---|---|
| **Host 组合** | 进程级：注册表本身（tools/systemPrompt/agents/sessions）、跨会话的存储/权限/沙箱/模型路由 | 进程一份，常驻 |
| **Agent preset 组合** | 每个会话贡献什么：工具插件、人设、提示词片段、压缩策略 | 每会话一份，随会话挂载/卸载 |

> 判据不是「这事和 agent 有没有关系」，而是「**它是否必须跨会话共享**」。必须共享的放 host；随会话变动的放 preset。

### 1.2 作用域层级（scope chain）—— 空间轴的核心

```
全局层 (global)
   └─ agent preset 常驻挂载（父作用域，standing mount）
        └─ 每个存活 agent（子作用域，每 agent 一个）
```

两条相反方向的规则：

- **注册视图「向下」继承**：子作用域看得见祖先各层；同名时**最近者遮蔽最远者**（nearest-wins）。
- **事件放行「向上」扩展**：标签为祖先的监听器能收到子孙的事件；**反向永不成立**。

> 白话：**上层定全局默认，下层可覆盖；广播从下往上流，不能从上往下灌。**

### 1.3 层（layer）与域（realm）

- **层**：一个注册表有「全局层 + 每个精确作用域的层」，读取时沿作用域链 `merge`，按插入序做具名遮蔽。`peek()` 只读自己这层——**自己的限制/守卫不得悄悄继承祖先的**。
- **域（realm）**：决定一个服务是「进程全局」还是「每会话隔离」。硬规则：**在 preset 里裸注册一个会发布服务的插件行是禁止的**，必须用带 `isolate` realm 的 group 把「服务提供者 + 它的所有消费者」包在一起，否则第二个会话挂载时冲突。

## 2. 时间轴：谁在何时生灭（Lifecycle / Generation / Version）

### 2.1 Cordis 生命周期（最底层的时间规则）

每个插件就是一个 `apply(ctx)` 函数，里面的贡献必须能被**精确撤销**：

```
apply（注册）→ effect/on（产生副作用）→ dispose（撤销）
```

- `ctx.effect()` 返回 disposer；
- 停止/更新/移除插件时按序 teardown；
- **没有「进程级、页面级」的泄漏副作用**。

这是时间组合性的地基：**每项贡献都带着自己的撤销函数**，所以「拔掉」是可逆的、可预测的。

### 2.2 常驻挂载与「世代」(generation)

preset 用 `standingKeyFor(id)` 做挂载校验：它**真的把 preset 的插件子树组合一遍**。成功会安装一个「**常驻世代**」，一直活到进程退出；失败则整体 dispose、不留痕迹。

### 2.3 动态插件的版本时序（plugin / package / run）

三个时间概念，区分得很清楚：

| 概念 | 含义 | 可逆性 |
|---|---|---|
| **Plugin** | 稳定实例（`pluginId`） | 长期存在 |
| **Package** | **不可变**的代码版本（`packageId`） | 改代码 = 追加新 package，不覆盖旧的 |
| **PluginRun** | 每次激活尝试（`pluginRunId`） | 单次 |

由此派生明确的时序语义：`run`（首次/重启/回滚）、`update`（切新版本）、`stop`（暂停保留版本）、`undefine`（永久删除），并带 current/next 两个版本指针支持「更新失败 → 回滚」。

## 3. 锚点契约：两条轴怎么「合」起来

> **注册的上下文同时决定「可见性」和「所有权」，防止一个注册在 A 作用域可见、却随 B 作用域被销毁。**

这就是时空组合性要解决的真正问题——**空间（谁看得见）和时间（谁生灭）必须由同一锚点绑定**，否则会出现「幽灵注册」：看得见的东西已经死了，或活着的东西看不见。

## 4. 迁移到机器人热插拔（本项目的核心映射）

| 机器人热插拔需求 | 时空组合性对应机制 |
|---|---|
| 运行时插入新传感器/夹爪/相机 | 在 robot 作用域注册插件工具 → 立刻可见可用（空间 + 时间） |
| 运行时拔出/替换某模块 | dispose 该插件 → 精确 teardown（时间） |
| 多末端执行器/多设备共存 | 每模块一个子 scope，父链继承，同名「最近者胜」（空间） |
| 同型模块互不串台 | `isolate` realm 隔离（空间） |
| 升级模块不重启整机 | Package 不可变 + `run`/`update` 回滚（时间） |
| 能力只对某 agent/会话可见 | 全局层 vs preset 层 vs 每 agent 层（空间） |
| 增删能力被决策层感知 | 事件广播 + agent 订阅（时间 + 空间） |

## 5. 术语速查

| 术语 | 一句话 |
|---|---|
| plane | 平面：host（进程级）vs agent preset（每会话） |
| scope | 作用域：带标签的上下文，注册随它可见、随它生灭 |
| scope chain | 作用域父链：视图向下继承、事件向上扩展 |
| layer | 层：一个注册表的全局/精确作用域贡献，读取时沿链 merge |
| nearest-wins | 最近者胜：同名注册沿父链遮蔽 |
| realm / isolate | 域/隔离：控制服务是进程全局还是每会话隔离 |
| apply / effect / dispose | Cordis 生命周期三件套：注册 / 副作用 / 撤销 |
| standing mount / generation | 常驻挂载/世代：preset 校验通过后安装的长期组合 |
| plugin / package / run | 动态插件的时间三级：实例 / 不可变版本 / 激活尝试 |
| anchor contract | 锚点契约：注册上下文 = 可见性 + 所有权 |
